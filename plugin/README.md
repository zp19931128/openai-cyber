# CPR 插件使用

面向 Linux x86_64、CPR 3.48.0。安装方法见[根目录说明](../README.md#通过-github-安装)。在现有插件实例上更新安装包，保留配置，并核对实例、`request` 绑定和拒绝故障策略已启用。

## 查看已配置规则

在 CPR 的插件页面入口打开“规则与拦截日志”，默认进入“规则管理”。顶部显示规则总数、启用与停用数量、词库版本和配置版本；列表包含全部内置规则和当前实例的补充规则。

输入名称、规则 ID 或短语搜索，也可按来源、状态和类别筛选。展开“查看匹配条件”可看到短语、条件组、匹配距离和英文单词边界设置。

内置规则可以通过开关启用或停用，内容随安装包维护。补充规则可以编辑或删除；如需增加内置规则以外的条件，点击“新增规则”。

v0.3.3 增加“App 脱壳与破解滥用”类别，含 8 条中英文内置规则：脱壳／逆向用于盗版、绕过授权／付费校验用于盗版或逃避付费、App 逆向窃密、App 逆向用于明确未授权访问。按“来源 → 内置规则”和此类别筛选，可逐条开关；已有模型越狱规则在“恶意模型越狱（破甲）”类别。新规则默认启用，原有停用列表和补充规则保留；切换后仍须点击“保存并生效”。

仅提到脱壳、逆向或破甲不会直接触发这些组合规则；完整滥用指令的引用仍可能误拦，词库也可能漏检，不等同于完整政策判定。建议先使用“测试当前规则”验证自己的正常请求和拒绝样例，再用于生产。

## 新增与编辑规则

按需要选择规则类型：

| 类型 | 如何填写 | 何时拦截 |
| --- | --- | --- |
| 关键词 | 在“拦截短语”填写一条明确短语 | 包含该短语即拦截，建议避免仅填写“扫描”等常用词 |
| 组合规则 | 填写名称、唯一规则 ID、类别和条件组，每组每行一个备选短语 | 每组各命中至少一个短语，且位于同句、指定字符距离内 |
| 正则 | 填写 Rust regex 表达式 | 在规范化后的单句上匹配，不支持环视或反向引用 |

不确定格式时可点击“填入示例”。组合规则默认生成规则 ID，可以修改；类别默认 `custom`，也可填写自己的类别。英文短语需要完整单词匹配时，开启“检查英文单词边界”。

填写后点击“校验并加入待保存”。配置无效时表单显示错误；校验通过后返回列表，顶部显示“有未保存修改”。编辑补充规则、确认删除、切换内置开关也只是修改当前页面的草稿。

## 测试与保存

1. 展开“测试当前规则”，输入一段文本并点击“运行测试”。测试使用当前草稿；命中时显示规则 ID 和类别。
2. 确认修改后点击“保存并生效”。保存成功后，刷新整个 CPR 页面或重新打开插件页面，再继续查看或修改。
3. 需要放弃草稿时点击“重新加载”，确认后恢复已保存配置。

测试只做文本匹配，不调用模型，也不写入拦截日志。它不重建完整模型请求；实际请求中的系统指令、工具定义和工具结果等字符串也会被检查。未命中只表示没有触发当前词库。

保存使用 CPR 当前插件实例的原生配置，保留日志设置、绑定和其他实例属性，无需额外数据库。保存前校验规则，并检查配置版本，避免覆盖其他管理员的修改。遇到版本冲突或“保存结果未确认”，先重新加载并核对当前已保存内容；若无法重新加载，刷新整个 CPR 页面后核对，再重新编辑。

规则页面管理 `disabled_builtin_ids`、`extra_keywords`、`extra_regexes` 和 `custom_rules`。如需导入 JSON 或调整上下文保存开关，仍可使用 CPR 原生插件配置；字段示例见[补充规则](../README.md#补充规则)。

## 查看拦截日志

切换到“拦截日志”，可以搜索、按类别筛选、翻页，展开记录查看该次请求携带的消息文本。页面仅管理员可访问，默认每条上下文最多 4000 个 Unicode 字符并屏蔽常见密钥格式；仅保存被拦截或无法检查的请求。

每个实例最多保留 100 条、总计 192 KiB，保留 7 天并在读写时清理。升级前未记录的上下文无法补回。完整字段、脱敏范围、关闭上下文和存储限制见[拦截日志与上下文](../README.md#拦截日志与上下文)。
